3:T176c,<h2 id="the-one-that-gives-you-spread-open-meteo-ensemble-api">The one that gives you spread: Open-Meteo Ensemble API</h2>
<p><code>https://ensemble-api.open-meteo.com/v1/ensemble</code> — <strong>free, no key, CORS-enabled</strong> (callable straight from a browser), JSON, CC-BY-4.0 attribution. It returns <strong>every <a href="/rome-wiki/articles/weather/ensemble-forecasting/" class="wiki-link">ensemble</a> member's</strong> hourly time series, so you compute your own percentiles/PoP client-side.</p>
<ul>
<li><strong>Global models for NYC</strong> (<code>models=</code>): <code>gfs_seamless</code> (GEFS, 30+control), <code>ecmwf_ifs025</code> (ECMWF ENS, 50+control), <code>icon_seamless</code> (ICON-EPS, 39+control), <code>gem_global</code> (21). Comma-separate them for a ~119-member multi-model super-ensemble.</li>
<li>⚠️ <strong>Europe-only models return empty over NYC</strong> — <code>icon_eu</code>, <code>icon_d2</code>, <code>meteofrance_arpege_europe</code> give HTTP 200 with zero members outside their domain. Global models only.</li>
<li><strong>Member keys</strong>: single-model → <code>temperature_2m_member01…</code>; multi-model → <code>temperature_2m_member01_ncep_gefs_seamless</code> etc. (control run is the un-suffixed <code>temperature_2m</code>). Parser must handle both.</li>
<li><strong>Variables</strong>: <code>temperature_2m</code>, <code>precipitation</code>, <code>wind_speed_10m</code>, <code>apparent_temperature</code>, <code>cloud_cover</code>, + many more, all per-member. (<code>apparent_temperature</code> = Steadman <a href="/rome-wiki/articles/weather/feels-like-temperature/" class="wiki-link">apparent temperature</a>, year-round, per-member — so it too gets a spread band.)</li>
<li><strong>Horizon</strong>: <code>forecast_days</code> up to ~16 (35 via <code>gfs05</code>). <strong>Limits</strong>: ~10k calls/day, 5k/hr, 600/min, non-commercial.</li>
<li><strong>Honest precipitation probability</strong>: <code>api.open-meteo.com/v1/forecast?hourly=precipitation_probability</code> returns the member-fraction % directly — or compute your own from <code>precipitation_memberNN</code> (fraction of members > 0.1 mm). This is the <em>real</em> probability, not the public "wet-biased" one (see <a href="/rome-wiki/articles/weather/temperature-forecast-confidence-intervals/" class="wiki-link">Temperature forecast confidence intervals</a>).</li>
</ul>
<h2 id="deterministic--official-no-spread">Deterministic / official (no spread)</h2>
<ul>
<li><strong>US NWS</strong> <code>api.weather.gov</code> — free, no key, CORS <code>*</code>, US-only. <code>/points/{lat},{lon}</code> → hourly forecast with temperature, wind, <code>probabilityOfPrecipitation</code>, plus <strong>watches/warnings/alerts</strong>. But it's a <strong>single deterministic</strong> forecast (National Blend of Models) — no confidence bands. Use for the "official NWS line" + alerts. (From a browser, omit User-Agent — it's a forbidden header.)</li>
<li><strong>Commercial free tiers</strong> (Tomorrow.io, Visual Crossing, WeatherAPI, OpenWeather) — all return one value + one PoP; <strong>none expose plottable ensemble spread</strong> on free tiers, and most need a browser-exposed key. Not worth it for this use case.</li>
</ul>
<h2 id="raw-ensembles-heavy-server-side-only">Raw ensembles (heavy, server-side only)</h2>
<ul>
<li><strong>ECMWF Open Data</strong> and <strong>NOAA NOMADS/GEFS</strong> give the true ENS members, but as <strong>GRIB2</strong> binaries needing <code>wgrib2</code>/<code>cfgrib</code>/<code>eccodes</code> — no JSON, not browser-viable. Open-Meteo has already done this decoding for you.</li>
</ul>
<h2 id="historical-for-backtesting-your-forecasts">Historical (for backtesting your forecasts)</h2>
<ul>
<li><strong>Open-Meteo Historical</strong> (ERA5 reanalysis, 1940–present, JSON, free) for gridded "truth"; <strong>NWS station observations</strong> (KNYC/KLGA/KJFK/KEWR) for actual METAR obs. ERA5 has ~5-day latency and is a reanalysis, not point obs.</li>
<li><strong><a href="/rome-wiki/articles/weather/open-meteo-previous-runs-api/" class="wiki-link">Open-Meteo Previous Runs API</a></strong> — the key one for <em>forecast-accuracy</em> backtesting: <code>previous-runs-api.open-meteo.com/v1/forecast</code> serves each past hour's forecast at a <strong>fixed lead time</strong> (<code>temperature_2m_previous_day1..7</code>), so you compare it against the current best estimate to get K-day-lead error. Free, no key, CORS. Means you <strong>don't</strong> have to snapshot your own forecasts to build a "how accurate were we?" panel — Open-Meteo already archived them.</li>
</ul>
<h2 id="bottom-line">Bottom line</h2>
<p>For confidence bands from a browser with no backend, <strong>Open-Meteo Ensemble is the only game in town</strong>; pair it with <code>api.weather.gov</code> for the official number + alerts. Used in <a href="/rome-wiki/articles/weather/nyc-weather-dashboard/" class="wiki-link">NYC weather dashboard</a>.</p>
