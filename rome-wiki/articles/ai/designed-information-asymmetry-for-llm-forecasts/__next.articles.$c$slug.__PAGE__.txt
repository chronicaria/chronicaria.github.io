3:T1258,<p>The core problem in <a href="/rome-wiki/articles/ai/llm-agent-ensembles-for-forecasting/" class="wiki-link">LLM agent ensembles for forecasting</a> is correlation. If 100 agents use the same model, prompt, search results, and market data, they may converge beautifully toward a wrong probability. The crowd looks large, but its effective number of independent forecasters is small.</p>
<h2 id="infodelphi-pattern">InfoDelphi pattern</h2>
<p><a href="/rome-wiki/articles/ai/multi-agent-forecasting-frameworks/" class="wiki-link">InfoDelphi</a> solves this by splitting the evidence corpus into:</p>
<ul>
<li><strong>public evidence</strong>: the strongest, most relevant common context all agents need to communicate coherently.</li>
<li><strong>private evidence</strong>: disjoint peripheral evidence slices routed to different agents.</li>
</ul>
<p>Agents first forecast from their own packet. Then they exchange rationales and forecast again. The load-bearing trick is that agents share the reasoning trace, not just the number. A probability like "68%" is too compressed; a rationale can carry the private source, causal model, and uncertainty that led there.</p>
<h2 id="why-public-plus-private-matters">Why public plus private matters</h2>
<p>Too much public evidence makes agents redundant. Too little public evidence makes them talk past each other. The useful middle is common ground plus private specialization:</p>
<ul>
<li>common ground lets agents understand each other's claims.</li>
<li>private evidence reduces correlated error.</li>
<li>rationale exchange lets private evidence propagate.</li>
<li>confidence-weighted aggregation lets better-supported private views matter more.</li>
</ul>
<h2 id="for-a-crypto-portfolio-swarm">For a crypto portfolio swarm</h2>
<p>For a live altcoin system, the public packet might include:</p>
<ul>
<li>recent price and volume bars.</li>
<li>BTC and ETH regime.</li>
<li>market-wide risk-on or risk-off indicators.</li>
<li>current portfolio state.</li>
<li>fees, spreads, and liquidity limits.</li>
</ul>
<p>Private packets could be routed by desk:</p>
<ul>
<li><strong>momentum desk</strong>: returns, volume breakouts, cross-sectional strength.</li>
<li><strong>mean-reversion desk</strong>: stretched moves, funding extremes, RSI-style exhaustion.</li>
<li><strong>order-book desk</strong>: spread, depth, slippage, imbalance, liquidity gaps.</li>
<li><strong>news desk</strong>: token-specific announcements, exchange listings, regulatory items.</li>
<li><strong>social desk</strong>: narrative velocity, influencer concentration, bot-like spikes.</li>
<li><strong>on-chain desk</strong>: flows, active addresses, bridge activity, whale movements.</li>
<li><strong>tokenomics desk</strong>: unlocks, emissions, treasury behavior.</li>
<li><strong>regime desk</strong>: BTC dominance, volatility, correlations, macro calendar.</li>
<li><strong>skeptic desk</strong>: data-quality failures, manipulation risk, unavailable execution.</li>
</ul>
<p>The visual payoff is excellent: the site can show which private packets pulled the ensemble away from the market prior.</p>
<h2 id="failure-modes">Failure modes</h2>
<ul>
<li>Private packets that are different but not useful create noise, not wisdom.</li>
<li>If agents see each other's forecasts too early, they herd.</li>
<li>If the aggregator rewards confidence without calibration, persuasive agents dominate.</li>
<li>If all agents share the same aligned model family, private evidence helps but does not remove structural monoculture.</li>
<li>More deliberation rounds can make the system look more thoughtful while reducing independence.</li>
</ul>

<li>Should private packets be assigned randomly, by agent skill, or by learned specialization?</li>
<li>Can a dashboard estimate "effective number of independent agents" from forecast covariance before enough outcomes resolve?</li>
