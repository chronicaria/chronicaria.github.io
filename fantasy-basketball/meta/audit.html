What was broken

The 131 repaired occurrences resolved to 28 distinct broken targets in three families, and all three were invisible to the old checker.

  1. Suffixed surnames — 22 distinct players. Dossier filenames drop the terminal period — Players/BKN/Michael Porter Jr.md — but prose linked <span class="redlink" title="Not in this encyclopedia">Michael Porter Jr.</span> with it. Obsidian does not resolve that. This family was the overwhelming majority of the breakage. Repaired to the mandated path-qualified form, <a href="../players/bkn/michael-porter-jr.html">Michael Porter Jr.</a>, which preserves the rendered text.
  2. Diacritics and punctuation — 5 distinct players. <span class="redlink" title="Not in this encyclopedia">Hugo González</span> → Players/BOS/Hugo Gonzalez, <span class="redlink" title="Not in this encyclopedia">Karim López</span> → Players/MEM/Karim Lopez, <span class="redlink" title="Not in this encyclopedia">Nikola Topić</span> → Players/OKC/Nikola Topic, <span class="redlink" title="Not in this encyclopedia">P.J. Washington</span> → Players/DAL/PJ Washington, and the inverse case <span class="redlink" title="Not in this encyclopedia">Nolan Traore</span> → Players/BKN/Nolan Traoré, where the file carries the accent and the link did not.
  3. Wrong note title — 1 target. <span class="redlink" title="Not in this encyclopedia">Punt strategy in 2026-27</span> now points at the note that actually exists, Punt strategies for nine-category leagues.

No repair was a judgement call: every one of the 28 targets resolved to exactly one note in the vault under case- and diacritic-folded matching, with no ambiguity to break.

Why the previous audit said "None"

Data/audit_encyclopedia.py resolved each link twice: first by exact filename stem, then — on failure — by a case- and diacritic-folded key. A link that failed the exact match but succeeded the folded match was recorded as neither broken nor ambiguous. It was silently dropped.

Every one of the 131 defects above is precisely that shape. Since \(\text{norm}(\texttt{"Michael Porter Jr."}) = \text{norm}(\texttt{"Michael Porter Jr"})\), the fallback matched and the link was counted as fine. The check was not merely lenient: its lenient branch was the branch that every real defect took, which is the worst possible place for a false negative.

The script has been corrected. A link that resolves only after normalization is now reported as broken with a known fix, because that is what it is in Obsidian.

These 3 occurrences point at notes that do not exist and should. They are left in place deliberately — the vault treats a red link as a self-creating TODO, and deleting them would erase the intent.

All three are strategy syntheses adjacent to notes that already exist (Punt strategies for nine-category leagues, Category correlations and roster construction, Draft day checklist and decision rules) but are not duplicates of them. Each was left unlinked rather than force-fitted to a near neighbour, since collapsing a wanted synthesis into the closest existing title destroys the request without satisfying it.

Two further red links seen mid-audit — missing player dossiers for Rafael Castro (Bucks) and Isaiah Livers (Suns) — resolved themselves before the final pass when the concurrent writer created those notes. The red-link mechanism worked exactly as intended.

What this audit cannot detect

This audit checks structure only — that frontmatter keys exist, that files parse, that ## Open questions is present, that wikilinks resolve to real notes. Every one of those is a question about the shape of a file, not about whether anything written in it is true.

It therefore cannot detect semantic or arithmetic defects. A dossier can carry perfect frontmatter, resolve every link, parse cleanly, and state a projection that was never computed from any real input. A ranking table can be internally consistent, correctly formatted, and ordered by a number whose sign is inverted. Nothing in this file would notice.

That is not hypothetical. While this audit was reporting no issues of any kind, the projection engine contained fabricated shot volume — per-game FGA and FTA values invented rather than derived from a minutes-and-rate model — and a sign error that inverted the contribution of turnovers, a category where lower is better, so that the players hurting a roster most were promoted rather than demoted. Both defects survived every check in this file, because both produce structurally flawless notes. See Projection engine defects and corrections for the diagnosis and the repaired outputs.

The general lesson: a green structural audit is evidence that the vault is well-formed, and evidence of nothing else. Numerical claims need a separate check that recomputes them from inputs and compares; factual claims need a source. Treat "all checks passed" here as the beginning of verification, not the end of it.

Reproducing

python3 Data/check_links.py # link report python3 Data/check_links.py --json # machine-readable python3 Data/audit_encyclopedia.py # regenerates this note's structural sections

Note that audit_encyclopedia.py overwrites this file with its generated template. The narrative sections above — the defect analysis, the wanted-notes table, and the limits section — are hand-written and will be lost if it is rerun without first extending the generator to preserve them.

Open questions

  • Should player dossier filenames carry the terminal period (Michael Porter Jr..md) so that bare <span class="redlink" title="Not in this encyclopedia">Name</span> links resolve, or is the path-qualified form now the standing convention for every suffixed player?
  • Should dossier filenames and titles carry diacritics consistently? Four notes currently store the unaccented spelling in both filename and title while prose uses the accented form.
  • What is the cheapest recomputation check that would have caught the turnover sign error — a category-level correlation sanity test, or a full independent reimplementation of the z-score pipeline?
  • Which structurally valid citations are inaccessible because of paywalls, anti-bot responses, or login requirements?
  • Which rank and minute changes should trigger a new dated snapshot rather than overwriting the July 18 baseline?
