<h2 id="core-shift">Core Shift</h2>
<p>The right unit is not "one agent equals one hosted LLM call." The right unit is:</p>
<pre><code class="language-yaml">agent_spec:
  role:
  team_or_department:
  information_packet:
  tools_allowed:
  model_policy:
  activation_rule:
  output_schema:
  budget_ceiling:
</code></pre>
<p>The <a href="/rome-wiki/articles/basketball/nba-multi-agent-forecasting-company/nba-agent-company-structure-plan/" class="wiki-link">NBA agent company structure plan</a> can keep the full 408-agent theater, but the runtime should schedule only the agents whose outputs are needed. Most "agents" are role definitions, prompts, tools, memory scopes, and scorecards. Only some become model calls on a given day.</p>
<h2 id="provider-tiers">Provider Tiers</h2>
<table>
<thead>
<tr>
<th>Tier</th>
<th>Use</th>
<th>Candidate providers</th>
</tr>
</thead>
<tbody>
<tr>
<td>Local/free runtime</td>
<td>Research packets, summaries, low-stakes committee voices, website color.</td>
<td>Ollama, llama.cpp, vLLM, local OpenAI-compatible servers.</td>
</tr>
<tr>
<td>Free hosted APIs</td>
<td>Prototype live calls without a bill, accept quotas and instability.</td>
<td>Gemini API free tier, OpenRouter free models, Groq Free, Cloudflare Workers AI daily free allocation.</td>
</tr>
<tr>
<td>Cheap paid fallbacks</td>
<td>Keep the live demo from stalling when free quotas fail.</td>
<td>DeepSeek V4 Flash, Gemini Flash-Lite, Groq small models, Mistral Small, Fireworks, Together, DeepInfra.</td>
</tr>
<tr>
<td>Occasional reliable model</td>
<td>CEO memo, audit summaries, high-disagreement slate review.</td>
<td>OpenAI nano-class models, Gemini Flash/Flash-Lite, Mistral Small or Large, DeepSeek Pro.</td>
</tr>
</tbody>
</table>
<p>The free tier is useful for a showcase, but not as the only dependency. Free models can disappear, throttle, or degrade exactly when the site is most fun to watch. The engineering answer is a provider router with hard spend caps and graceful degradation.</p>
<h2 id="current-cheap-and-free-options">Current Cheap And Free Options</h2>
<table>
<thead>
<tr>
<th>Provider</th>
<th>Why it belongs in the shortlist</th>
<th>Caveat</th>
</tr>
</thead>
<tbody>
<tr>
<td>Local Ollama / llama.cpp / vLLM</td>
<td>Free per call after hardware cost; enough for summaries, role-played research desks, and structured extraction. Ollama exposes a local API; llama.cpp and vLLM can expose OpenAI-compatible servers.</td>
<td>Speed and context depend on Andrew's machine. Small local models should not be trusted for odds math or final forecasts.</td>
</tr>
<tr>
<td>Google Gemini API</td>
<td>Gemini 2.5 Flash and Flash-Lite show free-tier access in the developer pricing page; paid Flash-Lite is very cheap per million tokens.</td>
<td>Free-tier traffic may be used to improve products; rate limits are per project and vary by tier/model.</td>
</tr>
<tr>
<td>OpenRouter free models</td>
<td>One OpenAI-compatible API over many free model variants, including an <code>openrouter/free</code> router and <code>:free</code> model variants.</td>
<td>Free plan is request-limited and free models are not stable infrastructure. Good for diversity, not sole production.</td>
</tr>
<tr>
<td>Groq</td>
<td>Very fast open-model inference; official docs list Free plan limits and low paid prices for small/open models.</td>
<td>Free limits are org-level and can bind on RPM, RPD, TPM, or TPD.</td>
</tr>
<tr>
<td>Cloudflare Workers AI</td>
<td>Daily free allocation plus serverless open models; useful for small, cheap background agents close to a website deployment.</td>
<td>Pricing is in "neurons"; larger models burn the daily free allocation quickly.</td>
</tr>
<tr>
<td>DeepSeek API</td>
<td>DeepSeek V4 Flash is one of the best cheap paid reasoning fallbacks: long context, OpenAI-compatible base URL, tool calls, JSON output, and very low per-token prices.</td>
<td>Not free after credits; provider and model availability should be monitored. Legacy model aliases are deprecating.</td>
</tr>
<tr>
<td>Mistral API</td>
<td>Mistral Small 4 is a capable cheap model, and Mistral has a free API mode plus a pay-as-you-go Scale tier.</td>
<td>The free tier is limit-bound; paid pricing is still better as a fallback than as 408 constant calls.</td>
</tr>
<tr>
<td>Fireworks / Together / DeepInfra / Hugging Face Inference Providers</td>
<td>Good pay-as-you-go hosts for open models, often with batch discounts or provider routing. Hugging Face gives tiny monthly credits and can route to providers without separate accounts.</td>
<td>Usually not truly free at meaningful volume; use as fallback diversity and batch-processing lanes.</td>
</tr>
<tr>
<td>OpenAI nano-class models</td>
<td>Useful for reliable structured outputs, CEO summaries, and low-cost sanity checks if a tiny paid bill is acceptable.</td>
<td>Not free; should be capped and used only where reliability is worth it.</td>
</tr>
</tbody>
</table>
<h2 id="department-model-assignments">Department Model Assignments</h2>
<table>
<thead>
<tr>
<th>Department</th>
<th>Model policy</th>
<th>Reason</th>
</tr>
</thead>
<tbody>
<tr>
<td>Data &#x26; Historical Archive</td>
<td>Mostly code, no LLM by default.</td>
<td>Joins, timestamps, no-vig odds, possession stats, and leakage checks are deterministic.</td>
</tr>
<tr>
<td>Team Research Committees</td>
<td>Local model first; free hosted model only for changed teams or game-day teams.</td>
<td>Team packets should be cached and refreshed on news, injuries, and game days.</td>
</tr>
<tr>
<td>Prediction Department</td>
<td>Mix 3-7 cheap/free hosted models per game, with different evidence packets.</td>
<td>Forecast diversity matters more than agent count.</td>
</tr>
<tr>
<td>Aggregation Department</td>
<td>Deterministic calibration code plus one cheap LLM explanation.</td>
<td>Aggregation should be Brier/log-score-weighted math, not vibes.</td>
</tr>
<tr>
<td>Finance Department</td>
<td>Code for odds conversion, expected value, Kelly fraction, and bankroll rules.</td>
<td>LLMs should not do money math. They can write the market memo.</td>
</tr>
<tr>
<td>Risk &#x26; Audit</td>
<td>Code for rule gates plus one reliable small model for explanation and red-team review.</td>
<td>The veto should be mechanical where possible.</td>
</tr>
<tr>
<td>CEO Agent</td>
<td>Cheap reliable model, short context, cached slate state.</td>
<td>The CEO coordinates and narrates; it does not forecast.</td>
</tr>
</tbody>
</table>
<h2 id="agent-virtualization">Agent Virtualization</h2>
<p>Use three execution modes:</p>
<ol>
<li><strong>Virtual role mode:</strong> one model call asks a "microboard" to return the structured votes of several named committee roles. This is enough for ordinary team research updates.</li>
<li><strong>Independent call mode:</strong> each role gets a separate call only for high-disagreement games, injuries, playoff stakes, or showcase days.</li>
<li><strong>Code-only mode:</strong> the agent is a deterministic function with a title, scorecard, and audit trail.</li>
</ol>
<p>For example, an eight-agent Celtics committee can usually be one call:</p>
<pre><code class="language-text">You are the Celtics Game Prep Microboard.
Return JSON with separate fields for:
Team Chair, Roster Agent, Player Impact Agent, Lineup Agent,
Scheme Agent, Health Agent, G League Agent, Schedule Agent.
Each role must cite packet fields and give confidence.
</code></pre>
<p>That preserves the company interface while keeping inference calls sane.</p>
<h2 id="daily-runtime-budget">Daily Runtime Budget</h2>
<p>A regular-season slate should look more like 60-120 calls, not 408+ calls.</p>
<table>
<thead>
<tr>
<th>Cycle</th>
<th align="right">Calls</th>
</tr>
</thead>
<tbody>
<tr>
<td>Data ingest, stat joins, injury snapshots</td>
<td align="right">0 LLM calls</td>
</tr>
<tr>
<td>Teams not playing and no major news</td>
<td align="right">0 LLM calls</td>
</tr>
<tr>
<td>Playing team Game Prep Microboards</td>
<td align="right">2 per game</td>
</tr>
<tr>
<td>Game predictors</td>
<td align="right">3-7 per game</td>
</tr>
<tr>
<td>Aggregation explanations</td>
<td align="right">1 per game</td>
</tr>
<tr>
<td>Finance/risk memo</td>
<td align="right">1 per slate</td>
</tr>
<tr>
<td>Public website story cards</td>
<td align="right">0-3 per slate</td>
</tr>
</tbody>
</table>
<p>On a 10-game slate this is roughly 20 team calls, 30-70 prediction calls, 10 aggregation calls, and a few memo calls. The public site can still display the full hierarchy, because inactive agents show cached state, last vote, confidence drift, and "sleeping" status.</p>
<h2 id="forecast-diversity">Forecast Diversity</h2>
<p>Do not simulate diversity with 100 copies of the same model reading the same packet. That recreates the correlated-error problem from <a href="/rome-wiki/articles/ai/designed-information-asymmetry-for-llm-forecasts/" class="wiki-link">Designed information asymmetry for LLM forecasts</a>.</p>
<p>Use diversity along four axes:</p>
<ul>
<li><strong>Model diversity:</strong> Gemini, Groq-hosted open models, DeepSeek, Mistral, local models, OpenRouter free variants.</li>
<li><strong>Information diversity:</strong> one predictor sees injury scenarios first, another sees impact metrics first, another sees market-blind schedule context, another sees team-committee disagreements.</li>
<li><strong>Prompt diversity:</strong> base-rate forecaster, injury-counterfactual forecaster, player-impact forecaster, market-skeptic forecaster.</li>
<li><strong>Temperature and seed diversity:</strong> useful only after the first three are present.</li>
</ul>
<h2 id="backtesting-without-burning-money">Backtesting Without Burning Money</h2>
<p>Walk-forward backtesting should be tiered:</p>
<table>
<thead>
<tr>
<th>Backtest phase</th>
<th>Inference policy</th>
</tr>
</thead>
<tbody>
<tr>
<td>V0 deterministic</td>
<td>No LLMs. Build data, odds, possessions, player priors, and scoring.</td>
</tr>
<tr>
<td>V1 compressed company</td>
<td>One microboard per team per simulated game day, 3 predictors per game.</td>
</tr>
<tr>
<td>V2 selected theater</td>
<td>Full independent committees only for Christmas, trade-deadline week, playoffs, and high-edge games.</td>
</tr>
<tr>
<td>V3 live paper mode</td>
<td>Cached daily team state, full calls only for active slate teams.</td>
</tr>
</tbody>
</table>
<p>The historical backtest is where costs can explode invisibly. The rule should be: prove the deterministic spine first, then spend model calls only where they create measurable calibration lift.</p>
<h2 id="budget-modes">Budget Modes</h2>
<table>
<thead>
<tr>
<th>Mode</th>
<th>Goal</th>
<th>Runtime</th>
</tr>
</thead>
<tbody>
<tr>
<td>Free showcase</td>
<td>Spend $0 unless a user manually flips a paid flag.</td>
<td>Local models + Gemini/Groq/OpenRouter/Cloudflare free quotas.</td>
</tr>
<tr>
<td>Coffee-money mode</td>
<td>Keep the demo alive through throttling.</td>
<td>Free-first router with DeepSeek V4 Flash, Gemini Flash-Lite, Mistral Small, or Groq small-model fallback; daily hard cap.</td>
</tr>
<tr>
<td>Research mode</td>
<td>Measure whether extra agents help.</td>
<td>Batch jobs, provider price floor routing, selected historical windows.</td>
</tr>
<tr>
<td>Full theater day</td>
<td>Make the website spectacular for one slate.</td>
<td>Independently activate many agents, but declare a temporary budget ceiling first.</td>
</tr>
</tbody>
</table>
<p>Every API key should have a provider-side spend cap. Every scheduler run should have a local call cap. The dashboard should show daily tokens, dollars, skipped agents, and cache-hit percentage as part of the spectacle.</p>
<h2 id="recommended-prototype-stack">Recommended Prototype Stack</h2>
<p>Start with:</p>
<ol>
<li><strong>Local Ollama</strong> for research summaries and inactive-agent chatter.</li>
<li><strong>Gemini 2.5 Flash-Lite or Flash</strong> as the main free/cheap structured-output model.</li>
<li><strong>Groq</strong> for fast open-model prediction calls when rate limits permit.</li>
<li><strong>OpenRouter free models</strong> for extra forecaster diversity and visible model variety.</li>
<li><strong>DeepSeek V4 Flash</strong> as the paid emergency fallback behind a hard daily cap.</li>
<li><strong>Cloudflare Workers AI</strong> only if the website is deployed on Cloudflare and needs tiny edge-side calls.</li>
</ol>
<p>Avoid making the first version dependent on dozens of providers. The routing layer should support many, but the MVP should have three active lanes: local, free hosted, and one cheap paid fallback.</p>
