3:T1066,<p>In a multi-agent investment system, forecasting agents should not directly trade. They should emit structured beliefs, and portfolio agents should convert those beliefs into constrained positions.</p>
<h2 id="forecast-objects">Forecast objects</h2>
<p>For each asset and horizon, agents should produce:</p>
<ul>
<li>probability of positive return.</li>
<li>expected return or return quantiles.</li>
<li>downside probability, such as probability of a drawdown beyond a threshold.</li>
<li>confidence and evidence quality.</li>
<li>rationale and falsifier.</li>
<li>forecast horizon and expiration.</li>
</ul>
<p>This makes forecasts scoreable. Binary events can use <a href="/rome-wiki/wanted/brier-score/" class="wiki-link wiki-link-missing" title="Unwritten article — a research thread waiting to be followed">Brier score +</a> and log loss; return distributions can use pinball loss, CRPS, or calibration by quantile bucket.</p>
<h2 id="sizing-layers">Sizing layers</h2>
<p><strong>Market prior layer.</strong> For traded assets, the current price is already a compressed forecast. The system should ask what evidence justifies moving away from a passive baseline such as cash, BTC, ETH, or equal-weight.</p>
<p><strong>Mean-variance layer.</strong> Markowitz-style optimization can combine expected returns and covariance, but it is fragile when expected returns are noisy. In a toy system, it is best used with heavy shrinkage, max weights, turnover caps, and a benchmark comparison.</p>
<p><strong>Black-Litterman-style layer.</strong> A better conceptual fit is market prior plus agent views. Agents provide views with confidence; the optimizer blends them with an equilibrium or benchmark prior rather than treating agent expected returns as truth.</p>
<p><strong>Kelly layer.</strong> Kelly sizing links edge and odds to growth-optimal bet size, but full Kelly is brutal under estimation error. PolySwarm's quarter-Kelly idea is directionally right: use fractional Kelly, hard caps, and no leverage.</p>
<p><strong>Risk-manager layer.</strong> A separate agent or deterministic module should enforce constraints: max position size, max daily turnover, max drawdown, liquidity, spread, fee drag, stale data, and venue availability.</p>
<h2 id="why-this-matters-for-a-100-pet-project">Why this matters for a $100 pet project</h2>
<p>At $100, fees, spreads, and minimum order sizes dominate. That is actually good for a live visualization: the intellectually honest version should show how many apparent opportunities die in the execution layer.</p>
<p>The clean version is:</p>
<ul>
<li>run the whole system live in paper mode.</li>
<li>optionally mirror only low-frequency, high-confidence changes with the real $100.</li>
<li>display every blocked trade and the rule that blocked it.</li>
<li>compare against BTC, ETH, equal-weight, and cash.</li>
</ul>
