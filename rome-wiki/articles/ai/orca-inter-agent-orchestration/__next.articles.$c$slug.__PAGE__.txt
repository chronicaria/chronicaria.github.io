3:T14c9,<h2 id="three-levels">Three levels</h2>
<p>Use the lightest level that creates enough structure.</p>
<h2 id="level-1-direct-messages">Level 1: direct messages</h2>
<p>Use this when one agent needs to nudge, review, or ask another agent something.</p>
<pre><code class="language-bash">orca terminal list --json

orca orchestration send \
  --to &#x3C;codexTerminalHandle> \
  --subject "Please review Claude's API plan" \
  --body "Focus on backwards compatibility and tests. Reply with the top risks." \
  --type status \
  --json

orca orchestration check --terminal &#x3C;codexTerminalHandle> --unread --json
</code></pre>
<p>Group addresses also exist, including <code>@all</code>, <code>@idle</code>, <code>@codex</code>, <code>@claude</code>, and <code>@worktree:&#x3C;id></code>. Use groups for broadcasts, not for dispatch completion.</p>
<p>This is a message bus, not magic telepathy. An agent must either be instructed to check its inbox, or the coordinator must inject/deliver the relevant message into the terminal session.</p>
<h2 id="level-2-task-dispatch">Level 2: task dispatch</h2>
<p>Use this when a worker needs ownership and must report completion.</p>
<pre><code class="language-bash">orca orchestration task-create \
  --task-title "Claude reviews Codex diff" \
  --display-name "Review Codex diff" \
  --spec "Review the current worktree diff as a skeptical maintainer. Report correctness bugs, missing tests, and behavior risks. Do not edit files." \
  --json

orca terminal create --worktree active --title claude-reviewer --command "claude" --json
orca terminal wait --terminal &#x3C;claudeHandle> --for tui-idle --timeout-ms 60000 --json

orca orchestration dispatch \
  --task &#x3C;taskId> \
  --to &#x3C;claudeHandle> \
  --inject \
  --json

orca orchestration check \
  --wait \
  --types worker_done,escalation,decision_gate \
  --timeout-ms 900000 \
  --json
</code></pre>
<p><code>dispatch --inject</code> gives the worker a live preamble. That preamble tells the worker how to send <code>worker_done</code>, how to ask blocking questions, and which <code>taskId</code>/<code>dispatchId</code> define completion authority.</p>
<h2 id="level-3-coordinator-loop">Level 3: coordinator loop</h2>
<p>Use this for larger decomposition where Orca should manage dispatching ready work across available terminals.</p>
<pre><code class="language-bash">orca orchestration run \
  --spec "Split the checkout QA across available Claude and Codex agents, collect worker_done reports, and summarize blockers." \
  --max-concurrent 3 \
  --worktree active \
  --json
</code></pre>
<p>Then inspect:</p>
<pre><code class="language-bash">orca orchestration task-list --json
orca orchestration task-list --ready --json
orca orchestration gate-list --status pending --json
</code></pre>
<p>This is the most powerful form, but it is also the easiest to overuse. Start with manual dispatch until the coordination pattern is obvious.</p>
<h2 id="good-claude-plus-codex-patterns">Good Claude plus Codex patterns</h2>
<ul>
<li>Codex implements; Claude reviews the diff.</li>
<li>Claude proposes an architecture; Codex implements the smallest patch.</li>
<li>Codex writes tests; Claude searches for missing edge cases.</li>
<li>Claude summarizes docs and design constraints; Codex makes code changes.</li>
<li>Both independently investigate a bug; a coordinator compares reports before editing.</li>
</ul>
<p>Avoid letting both edit the same checkout at once unless the scope is extremely clear. For independent implementations, use separate worktrees. For review-only collaboration, same worktree plus separate terminals is often fine.</p>
<h2 id="worker-contract">Worker contract</h2>
<p>A dispatched worker should:</p>
<ul>
<li>Do only the assigned task.</li>
<li>Use <code>orca orchestration ask</code> for blocking questions.</li>
<li>Send exactly one <code>worker_done</code>, even on failure.</li>
<li>Include what it did, what it found, what remains, and relevant file paths.</li>
<li>Stop after completion so the coordinator can decide the next move.</li>
</ul>
<p>Example completion:</p>
<pre><code class="language-bash">orca orchestration send \
  --to &#x3C;coordinatorHandle> \
  --type worker_done \
  --subject "Review complete" \
  --body "Reviewed the Codex diff. Found one missing regression test and one edge-case bug in the empty-state path. No files modified." \
  --task-id &#x3C;taskId> \
  --dispatch-id &#x3C;dispatchId> \
  --json
</code></pre>
